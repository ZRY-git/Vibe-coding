# 前端改动自查（学英语变强）

把「这个项目的前端该怎么改」固化成一份可复用的清单，不靠临场记忆，
也避免为了顺手而改动超出需求的代码。

## 一、什么时候用 / 什么时候不用

**用**：动页面结构（`main.html` / `index.html`）、动样式（`style.css`）、加或改交互
（筛选、搜索、切换、按钮反馈、状态切换）。

**不用**（本 Skill 明确不管）：
- 战斗逻辑、数值平衡、怪物与武器行为（`game.js` 的战斗部分）—— 那块约束不同，要动需单独说明
- 文档、PRD、技术设计

## 二、动手之前：先取清单

按下面的清单过一遍**将要改的范围**，先说清「要新增什么、要复用哪个既有类或函数」，
再动手写。不许写完代码才补说明。

## 三、检查清单

### A. 结构与数据
- A1 **数据驱动**：列表内容必须从数据源（`mock-data.js` / `words.js`）过滤后重新渲染，
  不把结果写死在 HTML 或 JS 字面量里
- A2 **复用既有渲染函数**：优先改 `renderWords()` 这类已有函数，不另起一套并行渲染逻辑
- A3 **语义化标签**：列表用 `ul/li`；可点的用 `button`（带 `type="button"`）；
  输入框配 `label`，不用 `div` 冒充按钮
- A4 **单一数据源**：筛选只读同一份数据，不复制一份「筛选后数据」当第二真相

### B. 样式
- B1 **只用 `:root` 变量**：`--bg / --card / --ink / --muted / --muted-strong / --line / --green / --green-soft`，
  不写新的裸色值（`.word-status.doing` 的 `#f0c95c` 属历史遗留，不新增同类）
- B2 **不写内联 `style`**（`#title-input` 那处是历史遗留，不新增）
- B3 **复用既有类**：`.panel / .hint / .word-item / .word-status / .stat-grid` 等，少造新类
- B4 **页作用域**：主页新样式挂 `.page-home` 前缀，别漏到游戏版（Day 9 教训）
- B5 **窄屏不溢出**：新增的一行控件在 375px 宽度下不横向撑破、不压字（Day 9 教训）。
  验证方法（Day 12 教训）：无头浏览器有最小窗口宽度（约 504px），`--window-size=375` 不生效，
  直接截图会把「画面右侧被裁」误判成溢出。正确做法：外层页面放**定宽 iframe**（320 / 375 / 414 各一），
  读 iframe 内 `scrollWidth === clientWidth` 与关键元素 `getBoundingClientRect`，以数值为准，不以截图裁切为准。

### C. 交互与反馈（今天重点）
- C1 **三种状态齐全**：任何「筛选 / 搜索 / 切换」都要过三种情况 ——
  ① **有结果**：结果正常显示，且**命中数量看得见**
  ② **无结果**：给明确空状态文案（不白屏、不静默无反应），并给回到全部的方式
  ③ **清空恢复**：清空条件后回到未筛选的完整状态，计数与列表一起复原
- C2 **无效操作也有反馈**：点了没反应的地方必须给提示（Day 11 教训）；
  条件性出现的控件（如「返回上一页」）没有可用目标时必须隐藏，不许做成死按钮（Day 13 加练教训）
- C3 **状态可核对**：当前筛选项/条件在界面上看得见，不靠记
- C4 **无残留**：来回切页、重复点击、清空再选，结果不叠加、不错乱；
  定时类流程（模拟加载）离开时必须取消，不许把用户拽回去

### E. 可访问性（Day 13 加练起为正式检查项）
- E1 **可交互控件有可访问名**：`input` 配 `label`；导航、面包屑、状态组各带
  `aria-label` 或 `aria-labelledby`；内容区块用 `aria-labelledby` 指向自己的标题
- E2 **结果变化要能被听到**：计数/结果区用 `role="status" aria-live="polite"`，
  错误用 `role="alert"`，加载占位用 `role="status"` + `aria-busy`
- E3 **键盘可达 + 焦点可见**：只用 `<a>` / `<button>` 原生元素，不造 div 按钮；
  提供「跳到主要内容」入口；焦点用 `:focus-visible` 描边，跳转落点也有提示
- E4 **页内锚点与 hash 路由共存**：跳转锚点用不带 `#/` 前缀的地址，
  路由只认 `#/` 开头 —— 两者各管各的，互不污染

### D. 红线
- D1 **不碰战斗逻辑**：`game.js` 战斗相关函数一行都不改
- D2 **不顺手优化**：只改需求范围内；发现别的问题写进报告，等拍板
- D3 **不建多余文件**：新文件先说明用途
- D4 **说得出归属**：每个改动文件都能说清属于哪天的任务

## 四、改完之后：出结论

逐条给「检查项 / 结论 / 证据」，结论只有 **过 / 不过 / 不适用** 三种。
「证据」必须是能亲眼看到的东西（文件路径、命令输出、页面上看得见的现象），
不接受「已检查」「应该没问题」。

## 五、每次调用都留一行记录

调用结束后，在**本文件同目录**的 `调用记录.md` 末尾追加一行：

| 日期 | 触发场景 | 本次用到的检查项 | 结论 |

例：`| 2026-10-06 | 给主页单词列表加状态筛选 | A1 A2 B1 B3 C1 C2 C4 D1 | 2 项不过，修完复检通过 |`

这一行是「这个 Skill 真被用过」的证据，不是装饰。
