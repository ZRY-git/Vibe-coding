## 三、逐步清单

| 步 | 位置 | 命令 | 命令作用 | 成功现象 |
|---|---|---|---|---|
| 1 | 项目文件夹内 | `git config --global user.name` / `user.email` | 登记提交署名，GitHub 靠邮箱认领贡献 | 回读命令输出与设置值一致 |
| 2 | 项目文件夹内 | `git init -b main` | 让 Git 接管文件夹，建立历史存档库 `.git` | 输出 `Initialized empty Git repository`，出现 `.git` 文件夹 |
| 3 | 项目文件夹内 | 创建 `.gitignore`（含 `.env`） | 声明哪些文件永不记录、永不上传 | `git status` 中看不到 `.env` |
| 4 | GitHub 网页 | 头像 → New repository | 在云端创建一个空仓库 | 页面显示 `ZRY-git/Vibe-coding` + `Public` |
| 5 | 项目文件夹内 | `git remote add origin <仓库地址>` | 把云端地址登记为 origin | `git remote -v` 显示两条地址 |
| 6 | 项目文件夹内 | `git add -A` → `git commit -m "Day 2｜…"` | 放入待提交区并打包成一个存档点 | 输出 `3 files changed, 77 insertions(+)` |
| 7 | 项目文件夹内 | `git push -u origin main` | 推送到云端并建立跟踪关系 | 输出 `[new branch] main -> main`，退出码 0 |

关键提醒：第 4 步建仓库时不要勾选 README。若勾选，云端会自动生成一次提交，与本地历史起点不同，第 7 步推送会被拒绝（这是首次推送最常见的坑）。

## 四、敏感文件保护

- 保护对象：`.env`（Day 23 起存放数据库连接串等密钥）
- 机制：`.gitignore` 第 2 行写入 `.env`，Git 从源头不记录该文件
- 三层验证：
  1. `git check-ignore -v .env` 命中忽略规则（输出 `.gitignore:2:.env`）
  2. `git ls-files` 结果中没有 `.env`
  3. GitHub 网页文件列表中没有 `.env`
- 长期纪律：密钥、数据库连接串永不写入任何被 Git 跟踪的文件

## 五、验证方式

- 打开 https://github.com/ZRY-git/Vibe-coding ：能看到仓库与 `index.html` 等文件
- 确认敏感文件没有出现：文件列表仅 `.gitignore`、`AGENTS.md`、`index.html`，`.env` 不在其中

## 六、备注

- 本地状态栏若显示 `## main...origin/main [gone]`，属显示问题，不影响推送与拉取；在自己终端执行一次 `git fetch origin` 即可恢复正常显示。
- 回退原则：撤销历史一律用 `git revert`（新增反做提交，保留历史）；禁止 `git reset --hard` 与强制推送。
